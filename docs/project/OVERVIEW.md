# TBHStats — обзор проекта

**Дата:** 2026-05-31
**Статус:** реализованы US1+US2+US3 (Phases 0–5) и большая часть Polish (Phase 6); остаётся live-acceptance (T051) и QA-харнесс (Phase 7).
**Фича:** `001-tbh-stats-helper`

---

## 1. Что это

**TBHStats** — десктоп-виджет для **Windows 11**, помощник по статистике для idle-RPG **«Task Bar Hero» (TBH)**.

Помощник работает в режиме **observe-only**: он не вмешивается в игру (никаких ботов, авто-кликов, записи в память или инъекций ввода). Он лишь **наблюдает** за окном запущенной игры, **визуально считывает** показатели с экрана (OCR), вычисляет темпы добычи и помогает выбрать оптимальный этап для фарма.

Захват привязан к окну игры (а не к фиксированным координатам экрана), поэтому помощник продолжает работать при перемещении/изменении размера окна, на любом мониторе и при любом масштабе рабочего стола.

---

## 2. Зачем (ценность)

Игра **не показывает скорость фарма за час**. Игрок видит текущие значения золота/опыта, но не понимает, насколько эффективен текущий этап по сравнению с другими.

TBHStats закрывает этот пробел:

- вычисляет **золото/час**, **опыт/час**, **сундуки/час** на основе наблюдаемого прироста значений во времени;
- накапливает **историю по этапам** между сессиями;
- **ранжирует этапы** по эффективности и **рекомендует**, где фармить, под выбранную цель оптимизации.

Вместо догадок игрок получает обоснованный ответ: «фарми здесь — это лучший этап по золоту/час».

---

## 3. Объём v1 (что входит)

- **Визуальный захват с экрана (OCR)** — считывание чисел и текста из окна игры; машиночитаемого файла/API у игры нет.
- **Живые показатели** текущего забега в реальном времени.
- **История по 60 этапам** — 3 акта × 2 сложности (Normal / Nightmare) × 10 этапов.
- **Сравнение этапов** и **рекомендация** оптимальной цели для фарма.
- **Выбираемая цель оптимизации**: золото/час **или** опыт/час (по умолчанию — золото/час).
- **Опционально — графики** трендов показателей.
- **Учёт сундуков по 3 типам** (базовый/коричневый, редкий/синий, легендарный/красный); список типов расширяем через конфигурацию.

---

## 4. Приоритеты (User Stories)

| Приоритет | История | Содержание |
|-----------|---------|------------|
| **P1 (MVP)** | Живая статистика текущего забега | Золото/час, опыт/час, сундуки/час, класс / уровень / урон героя, текущий этап. Минимально жизнеспособный продукт — ценность сразу, без истории. |
| **P2** | История этапов + ранжирование + рекомендация | Накопление истории по каждому этапу, таблица сравнения с сортировкой, подсветка оптимального этапа под выбранную цель. Главная аналитическая ценность. |
| **P3** | Графики трендов | Динамика золото/час, опыт/час и времени прохождения во времени; помогает заметить, когда этап «выработан». |

Каждый приоритет надстраивается над предыдущим: P2 невозможен без живого захвата P1, P3 — без накопленных данных P1/P2.

---

## 5. Что НЕ входит (Out of Scope v1)

- **Полноценное Android-приложение и удалённый сетевой доступ** — только задел в модели данных (пригодность к будущей удалённой выдаче), без реализации.
- **Любая автоматизация / вмешательство в игру** (бот, авто-клики) — продукт исключительно наблюдательно-аналитический (observe-only).
- **Учёт offline/idle-прироста** без запущенного помощника — измеряется только активное время, когда помощник и игра работают одновременно.
- **Подвкладки разделов** — учитываются только разделы верхнего уровня.
- **Автоматическое переключение разделов** игрой или помощником — обновление оппортунистическое, по действиям игрока.
- **Многопользовательские / облачные сценарии**, синхронизация между несколькими ПК.
- **Не считываемые в v1 разделы**: Stash, Runes, Cube, Settings, Trade ship, Mail Box. В v1 источники данных — только **Hero** (золото + инвентарь), **Status** (Level/EXP/Attack Damage), **Portal** (идентификатор текущего этапа), плюс основная игровая зона (сундуки, прогрессбар/босс, следующая локация).

## 6. Стек (кратко)

| Слой | Технология |
|------|------------|
| Платформа / язык | **.NET 8 (LTS) / C# 12** |
| UI-виджет | **WinUI 3** (Windows App SDK); WPF как fallback для оверлей-оболочки |
| Захват экрана | **Windows.Graphics.Capture** (WGC) по HWND окна игры |
| Распознавание | **Windows.Media.Ocr** (встроенный) |
| Хранилище | **SQLite через EF Core** (`%LOCALAPPDATA%\TBHStats\tbhstats.db`) |
| Графики | **LiveCharts2** (`LiveChartsCore.SkiaSharpView.WinUI`); ScottPlot как альтернатива |
| MVVM | `CommunityToolkit.Mvvm` |
| Тесты | xUnit + FluentAssertions (Core / Data) |

Решение мультипроектное: `TBHStats.Core` (домен, без платформенных зависимостей), `TBHStats.Capture` (Windows-слой захвата/OCR), `TBHStats.Data` (EF Core / SQLite), `TBHStats.App` (WinUI 3), `TBHStats.Remote` (задел на будущее).

Детали архитектуры — в [ARCHITECTURE.md](./ARCHITECTURE.md).

## 7. Дорожная карта

- **v1 — десктоп-виджет** (текущая фича `001-tbh-stats-helper`): живая статистика, история этапов, рекомендация, опциональные графики.
- **Будущее — Android-приложение** на **.NET MAUI**, удалённо подключающееся к TBHStats для просмотра живой статистики. Ключ к этому — **переиспользование доменного ядра `TBHStats.Core`** (без UI и без WinRT-зависимостей) и заложенный модуль `TBHStats.Remote` (будущий локальный API).
