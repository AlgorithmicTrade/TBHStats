# UI Test Scenarios: TBHStats QA-харнесс (аудит интерфейса живой игры)

**Feature**: `001-tbh-stats-helper` | **Date**: 2026-05-31
**Связано**: FR-022…FR-027, SC-012…SC-014, research.md R12, constitution §Security (carve-out)

## Назначение

Детерминированные («нехрупкие») E2E-тесты поверх **реально запущенной** игры Task Bar Hero. Харнесс сам аудирует интерфейс: визуально находит разделы/кнопки (OCR названий, переиспользуя слой захвата), навигирует между ними человекоподобными кликами и проверяет, что помощник корректно определяет активный раздел, следит за окном и читает привязанные значения.

## Инструментарий (R12)

- **xUnit** (раннер) + **FlaUI** (UIA + нативный ввод/окна) + **TBHStats.Capture** (WGC-кадр + OCR/ROI для локализации элементов) + **SendInput** (через FlaUI) для кликов.
- **Не** Playwright (браузерный) — применим только если TBH окажется Electron с CDP (проверяется в TS-00).

## Общие принципы (применяются ко всем сценариям)

- **Человекоподобный ввод (FR-024)**: клик в **случайную точку строго в пределах bounding box** целевого элемента (не центр); **случайная задержка** между действиями в диапазоне (по умолчанию **150–600 мс**, конфигурируемо); перемещение курсора с easing.
- **Нехрупкость (FR-025)**: перед действием/проверкой — **ожидание** ожидаемого состояния (poll-with-timeout, по умолчанию до 5 с); ассерты по **распознанному состоянию** (название активного раздела, читаемость поля), не по пикселям.
- **Детерминизм (SC-012)**: один и тот же сценарий на одной версии игры даёт одинаковый вердикт; серия из N прогонов — стабильность ≥98%.
- **Безопасность (FR-026, SC-013)**: **Safety-Guard** запрещает клики по координатам элементов из запрещённого списка. Запрещено нажимать: апгрейды в **Runes**, крафт/переработка в **Cube**, перемещение предметов в **Stash**, любые действия в **Trade ship**, продажа/трата в любом разделе. Разрешено: переключение разделов, открытие просмотровых видов, нажатие лупы Status (только переключение режима отображения).
- **Изоляция**: проект `TBHStats.UiTests` не входит в поставку; запускается только в явном тест-режиме.

### TS-02 — Верификация источников данных (data-source binding)
- **Цель**: подтвердить привязки «поле → раздел» (FR-002b).
- **Шаги/Ассерты**:
  - Открыть **Hero** → поле `gold` (вверху) читаемо и валидно.
  - Открыть **Status** → `heroLevel`, `xp`/`xpToLevel`, `heroDamage` читаемы.
  - Открыть **Portal** → `stageId` (акт/сложность/этап) читается; формат соответствует «акт-этап» (1-1…3-10).
  - На разделе, где поле НЕ привязано (напр. `gold` при открытом Status), помощник не обновляет это поле и не выдаёт ошибку (последнее достоверное).
- **Покрывает**: FR-002, FR-002b, SC-002.

### TS-03 — Следование за окном (move/resize/monitor)
- **Цель**: считывание продолжается без перекалибровки (FR-005b).
- **Шаги**: через FlaUI переместить окно игры, изменить размер, перенести на другой монитор (если доступен); между шагами — ожидание.
- **Ассерты**: активный раздел и привязанные поля по-прежнему читаются; ручная перекалибровка не требуется (SC-009).
- **Покрывает**: FR-005b, SC-009.

### TS-04 — Устойчивость к перекрытию/сворачиванию
- **Цель**: перекрытие/сворачивание = ожидание, не ошибка (FR-005/008).
- **Шаги**: вывести поверх игры другое окно; затем свернуть игру; затем восстановить.
- **Ассерты**: при перекрытии захват продолжается (WGC); при сворачивании — статус «ожидание», без ошибок и без записи мусора; после восстановления считывание возобновляется ≤5 с (SC-008); 0 «мусорных» записей (SC-007).
- **Покрывает**: FR-005, SC-007, SC-008.

### TS-05 — Аудит человекоподобности ввода
- **Цель**: проверить FR-024.
- **Шаги**: серия навигационных кликов с логированием точек и задержек.
- **Ассерты**: 100% точек кликов внутри границ целевого элемента; задержки распределены в заданном диапазоне (не константа); присутствует вариативность координат (не один и тот же пиксель).
- **Покрывает**: FR-024, SC-014.

### TS-06 — Safety-Guard (запрет мутаций)
- **Цель**: подтвердить, что харнесс не выполняет необратимых действий (FR-026).
- **Шаги**: прогнать TS-01 с включённым аудитом Safety-Guard; попытаться (в dry-run) адресовать запрещённый элемент.
- **Ассерты**: Safety-Guard блокирует и логирует любой запрещённый клик; за весь прогон **0** фактических нажатий по запрещённым элементам (Runes/Cube/Stash/Trade).
- **Покрывает**: FR-026, SC-013.

### TS-07 — Детекция активного раздела устойчива к шуму
- **Цель**: FR-002a при курсоре/всплывашках.
- **Шаги**: навести курсор рядом с названием раздела, вызвать тултип игры (если есть), затем проверить детекцию.
- **Ассерты**: активный раздел определяется верно ≥98% (SC-011); при невозможности достоверно определить — значения не приписываются неверному источнику.
- **Покрывает**: FR-002a, SC-011.

### TS-08 — Детерминизм (повторяемость)
- **Цель**: SC-012.
- **Шаги**: прогнать набор активных сценариев (TS-02, TS-05, TS-06; TS-01 отключён) N раз (по умолчанию N=5).
- **Ассерты**: вердикты совпадают между прогонами; стабильность ≥98% (флакийность ≈0).
- **Покрывает**: FR-025, SC-012.

### TS-09 — Восстановление «игра не найдена»
- **Цель**: graceful-поведение при отсутствии игры (US1 сц.4).
- **Шаги**: запустить харнесс без игры (или закрыть игру в процессе) → затем запустить игру.
- **Ассерты**: статус «игра не найдена» без падения; после появления окна харнесс/помощник подхватывают её и продолжают.
- **Покрывает**: FR-001, FR-005.

### TS-10 — Подвкладка по умолчанию (Hero → Inventory)
- **Цель**: при открытии Hero активна подвкладка Inventory (контекст спеки; подвкладки вне объёма, но дефолт проверяем).
- **Шаги**: открыть Hero → проверить, что отображается Inventory.
- **Ассерты**: видна инвентарная зона; `gold` сверху читается. (Composition не открываем — навигация безопасна.)
- **Покрывает**: контекст FR-002a (Hero).
